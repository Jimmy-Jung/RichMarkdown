# RichMarkdown 개선 기록

기준일: 2026-10-06 · 대상: **0.9.0**

각 모듈에서 무엇이 잘못됐고 어떻게 바뀌었는지 정리합니다. 수정 전 동작, 코드에 반영한 내용, 다시 깨지지 않는지 확인한 검사, 남은 조건을 구분했습니다. 실행·배포 상태는 [검수 기록](../validation.md), 낯선 용어는 [용어 안내](../glossary.md)를 참고합니다.

| 항목 | 반영 내용 | 상세 기록 |
| --- | --- | --- |
| Core 입력·위치 | 줄바꿈 형식별 원문 위치 계산, 수식 구간을 찾기 전 인용 깊이 검사, 위치 덧셈의 범위 검사 | [Core](RichMarkdownCore.md) |
| 표시 모듈의 코드 색·표 | 잘못된 색칠 구간 거절, 현재 코드·언어·공급자의 결과만 표시, UIKit 표의 실제 셀 높이 측정 | [표시 모듈](RichMarkdown.md) |
| 편집기의 입력·저장 | 숫자·선택·입력기 범위 검사, 문법처럼 생긴 문단의 문자 보존, 코드 구분 기호 길이 조절 | [편집기](RichMarkdownBlockEditor.md) |
| Mermaid 대기·복구 | 페이지 준비 공유와 호출별 취소, 앱 쪽 대기 시간 제한, 최신 그림 반영, 웹 프로세스 종료 복구 | [Mermaid](RichMarkdownMermaid.md) |
| Mermaid 보안 | 위험 태그 제거 설정의 변경 차단, 초기 코드 해시로 스크립트 실행 제한, 포함 라이브러리 보안 수정 | [Mermaid](RichMarkdownMermaid.md), [번들 근거](../../CODE_BLOCK_EXTENSIONS.md) |

코드 길이를 제한해도 JavaScript가 문법별 색칠 구간을 찾는 데 걸리는 최대 시간까지 보장되지는 않습니다. [코드 색칠의 실행 시간 검토](RichMarkdownHighlight.md)는 실제 지연을 측정하거나 반드시 지켜야 할 시간 제한이 생길 때 다시 검토합니다. 재현 근거 없이 JavaScript 엔진 교체나 강제 중단 API를 추가하지 않았습니다.

편집기는 지원하는 블록과 인라인 서식을 Markdown으로 저장하고 다시 읽었을 때 그 의미를 보존합니다. 모든 Markdown 원문 바이트, 빈 문단 개수, 임의의 코드 언어 표기를 그대로 보존하는 편집기로 확대하지 않았습니다.
