# RichMarkdownHighlight 개선안

기준일: 2026-10-06 · 상태: **제안 — 적용·승인 전**

이 문서는 코드 분석 엔진의 실행 시간과 취소를 개선할 방향을 현재 동작과 분리해 기록합니다. 아래 IH-01은 아직 코드와 테스트에 반영하지 않았으며 새 동작을 [명세](../spec/RichMarkdownHighlight.md)의 보장으로 포함하지 않았습니다. 화면에 이전 색이 남던 문제는 `RichMarkdown` 모듈에서 별도로 수정했으며 마지막 절에서 구분합니다.

Prism은 코드 원문을 키워드·문자열·주석 같은 조각(토큰)으로 나누는 라이브러리입니다. `PrismHighlighter` actor가 JavaScript 실행 환경(`JSContext`)을 관리합니다. actor는 공유 상태 접근을 보호하는 Swift 타입이며, 여기서는 같은 실행 환경의 토큰 분석을 겹치지 않게 합니다.

## IH-01. 코드 분석 시간과 실행 중 취소

**정적 관찰:** 코드를 읽어 확인한 구조상, [spans](../../../Sources/RichMarkdownHighlight/PrismHighlighter.swift#L78)는 입구에서 취소를 검사하고 입력 길이를 제한합니다. 하지만 [tokenize](../../../Sources/RichMarkdownHighlight/PrismHighlighter.swift#L127)의 동기 `function.call`에는 실행 중 취소나 시간 제한이 없습니다. 같은 actor에서 토큰화를 순서대로 실행하므로 오래 걸리는 요청은 같은 인스턴스의 후속 요청을 기다리게 합니다.

**발생 조건과 영향:** 제한 이내의 코드라도 문법별 문자열 패턴을 찾는 정규식 분석에 긴 시간이 들면, 스트리밍 갱신에서 이미 취소한 요청이 계속 실행되고 새 코드의 색 적용이 지연될 수 있습니다. 실제 장시간 실행·메모리 증가는 이번 문서 작업에서 재현하거나 측정하지 않았습니다. 입력 길이 상한만으로 최대 실행 시간을 보장할 수 없다는 구조가 확인 대상입니다.

**최소 변경 제안:** 먼저 대표 문법에서 길이 상한에 가까운 입력과 정규식 처리 비용이 큰 입력의 실행 시간·후속 요청 지연을 측정합니다. 반환 직전 취소 검사를 추가하면 더는 필요 없는 색 구간(span)의 전달을 줄일 수 있지만 동기 실행을 중단하지는 못합니다.

정해진 시간 안에 반드시 종료해야 하는 기한(deadline)이 제품 요구가 되면, 엔진 실행 자체를 중단할 방법을 별도로 설계합니다. Swift Task에 시간 초과 처리(timeout)를 추가했다고 해서 동기 엔진 실행까지 중단됐다고 보고하지 않습니다.

**의미 있는 확인:** 느린 요청 도중 요청 Task를 취소하고 후속 요청을 넣어 실제 대기 시간과 결과 반영 여부를 확인합니다. UTF-16 길이 100,000과 100,001의 경계도 함께 확인합니다. UTF-16은 UIKit의 `NSRange`에 쓰는 위치 단위로, 이모지 하나가 두 단위를 차지할 수 있으므로 화면의 글자 수와 다릅니다.

기존 [PrismHighlighterTests](../../../Tests/RichMarkdownHighlightTests/PrismHighlighterTests.swift)는 문법 결과와 길이 초과 시 색 없이 원문을 남기는 대체 동작(fallback)을 다루지만, 시간 상한·실행 중 취소를 확인하지 않습니다.

**완료 기준:** 요구 종료 기한을 정하고 같은 실행 환경에서 앞 요청이 후속 요청을 얼마나 지연시키는지 실제 실행 근거를 남깁니다. 이 제안은 엔진 결함을 실제로 재현했다는 기록이나 새 엔진 선택 승인이 아닙니다.

## 화면 표시 코드에서 수정한 문제

개선 전에는 동일 코드에서 언어가 바뀌고 새 결과가 `[]`일 때 SwiftUI의 기존 `highlight` 색 상태가 남는 경로가 있었습니다. 하이라이터 인스턴스만 바꾼 경우에도 `.task(id:)`의 비교 기준에 포함되지 않아 새 공급자를 호출하지 않는 경로가 있었습니다. 두 문제는 하이라이터 엔진이 아닌 [RichMarkdownView.swift](../../../Sources/RichMarkdown/RichMarkdownView.swift)의 화면 상태 관리 문제입니다.

현재 `HighlightRequest`는 코드·언어·하이라이터 객체 참조를 함께 비교하고, 새 요청 시작 때 기존 색을 지웁니다. 반영 내용과 기존 회귀 결과는 [렌더러 개선 기록](RichMarkdown.md#render-imp-02-swiftui-코드-색-결과의-요청-일치-확인)·[검수 기록](../validation.md)을 따릅니다. 이 수정으로 동기 JavaScript 실행 중단이나 최대 실행 시간이 보장되는 것은 아닙니다.
