# 보고서 용어 안내

작성일: 2026-10-07

이 보고서에서 반복해서 쓰는 용어를 실제 처리 흐름에 맞춰 설명합니다. API 이름과 설정 키는 소스에서 검색할 수 있도록 그대로 적고, 뜻은 한국어로 풀어 씁니다. 각 문서에도 처음 등장하는 용어의 설명을 덧붙였습니다.

## 문서와 패키지 구조

| 용어 | 이 보고서에서 뜻하는 것 |
| --- | --- |
| 아키텍처(architecture) | 어느 모듈이 어떤 일을 맡고, 입력과 결과가 어디로 전달되는지 정리한 구조입니다. |
| 명세(spec)·동작 계약 | 앱이 라이브러리를 사용할 때 지켜야 할 입력 조건, 반환값, 실패 처리 규칙입니다. 법률상 계약을 뜻하지 않습니다. |
| ADR(Architecture Decision Record) | 구조를 선택한 이유, 다른 방법의 비용, 다시 검토할 조건을 기록한 문서입니다. 기존 코드를 읽고 작성한 기록은 과거 회의나 팀 승인을 증명하지 않습니다. |
| 패키지(package) | Swift Package Manager가 의존성과 소스를 묶어 관리하는 단위입니다. 이 저장소에는 패키지 하나가 있습니다. |
| 타깃(target)·모듈(module) | 함께 컴파일하는 소스 묶음과, 그 묶음을 `import`할 때 사용하는 단위입니다. 이 패키지의 라이브러리 타깃은 다섯 개입니다. |
| 공개 라이브러리(product) | 소비 앱이 패키지 설정에서 선택하는 라이브러리입니다. 공개 라이브러리는 네 개이며 `RichMarkdownCore`는 내부 타깃입니다. |
| 선택 기능(opt-in) | 앱이 명시적으로 켜거나 추가해야 사용하는 기능입니다. 예를 들어 달러 기호 수식 인식은 기본으로 켜져 있지 않습니다. |
| 공급자·구현체(provider) | 약속된 인터페이스에 따라 실제 일을 수행하는 객체입니다. 코드 색칠 공급자는 코드와 언어를 받아 색을 입힐 구간을 반환합니다. |

## 원문을 분석하고 위치를 보존하는 과정

**파싱(parsing)**은 Markdown 문자열을 제목·문단·목록 같은 구조로 읽는 과정입니다. **렌더링(rendering)**은 그 구조를 화면의 글자·표·그림으로 표시하는 과정입니다. 같은 문서를 분석하더라도 화면 색이나 글자 크기는 별도로 바뀔 수 있습니다.

| 용어 | 뜻과 사용 예 |
| --- | --- |
| 원문(source) | 앱이 전달한 Markdown, 코드, 수식 문자열입니다. 분석하거나 색을 입힌 결과와 구분합니다. |
| 구간(span)·범위(range) | 원문의 어느 부분을 처리할지 나타내는 시작 위치와 길이입니다. 코드 색칠에서는 단어 자체를 바꾸지 않고 해당 구간에 색만 입힙니다. |
| 구문 트리(AST, Abstract Syntax Tree) | 파싱 결과를 제목·목록·문단 등의 계층으로 나타낸 자료입니다. 원문 문자열이나 화면의 뷰 계층과는 다릅니다. |
| 제외 구간(barrier) | 수식처럼 생긴 문자열이라도 수식으로 읽지 않는 부분입니다. 코드 블록 안의 수식 기호가 대표적인 예입니다. |
| 임시 덮기(mask) | 수식 구간을 임시 문자로 덮어 Markdown 분석에서 보호하는 처리입니다. 원문 위치가 어긋나지 않도록 UTF-8 바이트 길이를 유지합니다. |
| 파싱 전 검사(preflight) | 구문 트리를 만들기 전에 입력 길이와 인용 깊이를 확인하는 처리입니다. 지나치게 큰 입력은 분석 전에 제한합니다. |
| 입력 정규화(canonical·normalized input) | 같은 규칙으로 비교·처리할 수 있도록 입력을 정리하는 과정입니다. 이 문맥에서는 입력 제한과 수식 인식 설정 등을 포함하며, 모든 원문을 같은 문자열로 바꾼다는 뜻은 아닙니다. |
| 이스케이프(escape) | 문법 기호를 기능이 아닌 문자 그대로 읽도록 표시하는 처리입니다. 문단의 `# 제목`이 저장 후 제목 블록으로 바뀌지 않게 할 때 사용합니다. |
| 코드 블록 구분 기호(fence) | 코드 블록의 시작과 끝을 표시하는 백틱 등의 기호입니다. 코드 본문에도 백틱이 있다면 바깥 구분 기호를 더 길게 선택합니다. |

### UTF-8·UTF-16·Character는 서로 다른 단위입니다

`A😀`를 단순한 예로 들면, Swift에서 보이는 글자 수(`Character`)는 2개, UTF-16 코드 단위는 3개, UTF-8 바이트 수는 5개입니다. 이모지 하나가 각 단위에서 차지하는 길이가 다르기 때문입니다. 따라서 글자 수로 얻은 위치를 UTF-16 범위에 그대로 넣으면 다른 부분을 가리킬 수 있습니다.

Core 파서의 원문 위치는 **UTF-8 바이트**를 기준으로 합니다. 편집기의 선택 범위와 코드 색칠 범위는 **UTF-16 코드 단위**를 기준으로 합니다. `NSRange`는 시작 위치(`location`)와 길이(`length`)를 담는 타입이며, 이 보고서의 텍스트 처리에서는 UTF-16 단위로 사용합니다.

**정수 범위 초과(overflow)**는 위치와 길이를 더한 값이 정수 타입의 표현 범위를 넘는 상황입니다. 잘못된 범위를 걸러낼 때는 덧셈 결과만 비교하지 않고, 더하기 전에 각 값이 원문 범위 안에 있는지 확인합니다. Swift 범위로 바꿀 때는 이모지 등의 문자 경계를 중간에서 끊지 않는지도 확인합니다.

## 비동기 요청과 최신 결과 표시

**비동기(async)**는 결과를 기다리는 동안 호출한 작업이 실행을 멈추고 나중에 이어갈 수 있다는 뜻입니다. 비동기 함수라는 이유만으로 항상 별도 스레드에서 실행되는 것은 아닙니다.

| 용어 | 뜻과 사용 예 |
| --- | --- |
| 요청 순서 번호(generation) | 어느 요청이 더 나중에 제출됐는지 구분하는 번호입니다. 이전 계산이 늦게 끝나도 현재 화면을 덮어쓰지 않도록 결과 반영 전에 비교합니다. |
| 같은 요청을 판별하는 기준(identity) | 원문·수식 인식 설정 등, 같은 계산을 재사용해도 되는지 확인하는 값입니다. 코드 색칠에서는 코드·언어·공급자 객체도 함께 비교합니다. |
| 캐시 키(cache key) | 저장해 둔 계산 결과를 찾는 기준입니다. 수식 이미지에는 수식 원문·색·크기 등이 필요하며 화면 요청의 순서 번호와는 용도가 다릅니다. |
| 최신 요청만 반영(latest-wins) | 여러 요청이 겹쳐도 가장 최근 요청의 결과만 현재 화면에 쓰는 규칙입니다. 이전 계산을 강제로 중단한다는 뜻은 아닙니다. |
| 대기 요청 합치기(coalescing) | 작업 하나를 실행하는 동안 대기 입력을 하나만 보관하고, 새 입력이 오면 그 대기 입력을 교체하는 방식입니다. 모든 중간 입력을 차례로 처리하지 않습니다. |
| 최대 수신 번호(high-water) | 지금까지 받은 가장 큰 요청 순서 번호입니다. 이미 더 최신 요청을 받은 뒤 늦게 도착한 이전 요청을 거절할 때 사용합니다. |
| 이전 요청의 결과(stale result) | 현재 입력이 바뀐 뒤 도착한 오래된 계산 결과입니다. 같은 계산 결과가 캐시에 저장될 수 있는지와 현재 화면에 표시할 수 있는지는 따로 판단합니다. |
| 결과 반영 조건(gate) | 계산 결과를 현재 화면에 써도 되는지 확인하는 조건입니다. 요청 번호·원문·설정이 현재 값과 맞는지 검사합니다. |
| 수식 이미지를 나중에 채우기(hydration) | 문서를 먼저 표시하고, 아직 없는 수식 이미지가 계산되면 나중에 화면에 채워 넣는 과정입니다. |
| 실패 시 원문 표시(fallback) | 수식이나 다이어그램을 만들지 못했을 때 원문을 보여 주는 대체 처리입니다. 기능마다 실패 표시의 길이 제한은 다를 수 있습니다. |

단순화한 예로, A를 계산하는 동안 B가 대기하고 C가 들어오면 B 대신 C를 대기시킵니다. A 계산이 끝났다는 사실만으로 A를 화면에 표시하지는 않습니다. 화면에 반영하는 쪽에서 현재 요청과 일치하는지 다시 확인합니다.

### actor·MainActor·Task 취소

**actor**는 자신이 관리하는 상태에 여러 작업이 동시에 접근하지 않도록 보호하는 Swift 타입입니다. 전용 스레드 하나를 뜻하지 않으며, 함수 안에서 `await`로 기다리는 동안 다른 호출이 상태를 바꿀 수 있습니다.

**`@MainActor`**는 화면 상태를 메인 실행 영역에서 다루도록 하는 표시입니다. **`Sendable`**은 값을 다른 동시성 실행 영역으로 전달해도 안전한지 나타내는 Swift의 규칙입니다. API 선언에 이 이름이 있으면 임의로 생략하거나 단순히 스레드 이름으로 해석하지 않습니다.

**`Task` 취소**는 실행 중인 작업에 중단 요청을 전달합니다. 작업이 취소 상태를 확인하고 처리해야 하며, 이미 JavaScript 엔진 안에서 실행하는 계산까지 자동으로 강제 종료하지는 않습니다.

## 수식 표시와 편집 내용 변환

| 용어 | 뜻과 사용 예 |
| --- | --- |
| 비트맵 이미지(raster) | 점들의 색으로 구성한 이미지입니다. 인라인 수식을 글자 사이에 넣는 경로에서 사용합니다. |
| 벡터 그림(vector) | 선과 윤곽선 정보로 그리는 그림입니다. UIKit의 블록 수식은 이 표시 경로를 사용합니다. |
| 글자 기준선(baseline) | 글자들이 한 줄에서 맞춰지는 기준입니다. 인라인 수식이 주변 글자보다 뜨거나 가라앉지 않도록 맞출 때 사용합니다. |
| 수식 배치(layout·조판) | 수식 기호의 크기와 위치를 정하는 과정입니다. 수식 인식과 최종 이미지 표시 사이의 단계입니다. |
| 텍스트 속 그림(attachment) | 텍스트 문서에 글자 대신 배치하는 그림 객체입니다. 편집기에서는 수식을 그림으로 보이다가 선택하면 원문으로 바꾸는 데 사용합니다. |
| 입력기 조합 중인 글자(IME composition) | 한글 등에서 입력이 아직 확정되지 않은 상태입니다. 범위 검사와 화면 변경이 조합 중인 글자를 깨뜨리지 않아야 합니다. |
| 변환 후 다시 읽기(round-trip) | 블록 모델을 Markdown으로 저장한 뒤 다시 블록으로 읽는 과정입니다. 이 편집기는 지원하는 블록·인라인 의미를 보존하며 모든 Markdown 바이트를 그대로 보존하지는 않습니다. |
| 복사 데이터(payload) | 클립보드에 실제로 담는 데이터입니다. 일반 Markdown 문자열과 앱 내부에서 블록 구조를 보존하는 데이터는 용도가 다릅니다. |
| 항상 유지할 조건(invariant) | 생성하거나 수정한 뒤에도 지켜야 하는 값의 범위나 관계입니다. 들여쓰기를 0...3으로 제한하는 것이 한 예입니다. |

## Mermaid의 웹 표시와 보안

Mermaid에서는 **앱 쪽(native)**의 Swift 코드가 웹 화면을 관리하고, **JavaScript 쪽**이 그림을 만듭니다. **브리지(bridge)**는 두 쪽이 원문·완료 결과·그림 크기를 주고받는 연결입니다. `WKWebView`는 앱 안에서 웹 문서를 표시하는 뷰입니다.

| 용어 | 뜻과 사용 예 |
| --- | --- |
| 웹 문서 구조(DOM) | 브라우저가 화면에 표시할 요소들을 보관하는 구조입니다. 최신 다이어그램 결과가 이 구조에 반영돼야 화면도 바뀝니다. |
| 완료 결과를 기다리는 객체(Promise) | JavaScript에서 나중에 성공하거나 실패할 작업의 결과를 나타내는 객체입니다. 끝나지 않는 Promise는 뒤 요청도 기다리게 할 수 있습니다. |
| 중단된 함수의 재개 수단(continuation) | 콜백이 끝났을 때 기다리던 Swift 비동기 함수를 다시 진행하게 합니다. 한 대기에 대해 성공·실패·취소 중 하나로 한 번만 완료해야 합니다. |
| 로드 완료를 기다리는 호출(waiter) | 웹 페이지 준비를 기다리는 개별 요청입니다. 준비 작업을 공유해도 한 호출의 취소가 다른 호출까지 취소해서는 안 됩니다. |
| 표시 전 임시 영역(staging) | 그림을 화면에 내보내기 전에 크기와 현재 요청 여부를 확인하는 숨긴 영역입니다. 보이지 않는다는 이유만으로 스크립트 실행이 안전해지는 것은 아닙니다. |
| 화면 갱신 단계(frame) | 브라우저가 화면 배치를 갱신하는 단위입니다. 임시 영역에서 최종 크기를 확인한 뒤 실제 화면에 반영합니다. |
| 완료 대기 제한(deadline·timeout) | 일정 시간 안에 끝나지 않으면 오류로 처리하는 기준입니다. Mermaid의 로드와 렌더 대기는 각각 15초이며 전체 처리 시간이 15초 이내라는 보장은 아닙니다. |
| 다시 읽어야 하는 상태(dirty) | 취소·시간 초과 등으로 기존 페이지의 실행 상태를 이어 쓰기 어려운 상태입니다. 다음 요청 전에 페이지를 다시 로드합니다. |
| 원문 안의 설정(directive·frontmatter) | 다이어그램 원문에 포함한 렌더 설정입니다. 표시 설정과 안전 설정을 구분하고, 입력이 안전 설정을 임의로 바꾸지 못하게 합니다. |
| 콘텐츠 보안 정책(CSP) | 실행할 수 있는 스크립트와 불러올 수 있는 자원의 출처를 제한하는 브라우저 규칙입니다. 허용한 초기 코드의 해시와 로컬 번들만 실행하도록 설정합니다. |
| 위험한 태그·속성 제거(sanitizer) | HTML·SVG에서 위험한 태그나 속성을 걸러내는 처리입니다. 화면에 보이기 전에 실행된 스크립트까지 되돌려 주지는 않습니다. |
| 초기 실행 코드(bootstrap) | 페이지를 준비하고 Mermaid 실행 함수를 연결하는 시작 코드입니다. 이 코드가 바뀌면 CSP에 적은 해시도 맞춰야 합니다. |
| 묶음 파일(bundle)·포함 의존성 | Mermaid와 함께 필요한 JavaScript 라이브러리를 묶어 앱에 넣은 파일입니다. Mermaid 본체 버전이 같아도 포함 라이브러리의 보안 수정으로 번들은 바뀔 수 있습니다. |

## 검사 결과를 읽는 방법

**회귀 테스트**는 수정 뒤 기존 기능이나 새로 고친 동작이 다시 깨지지 않는지 확인하는 검사입니다. **RED → GREEN**은 수정 전 테스트 실패를 확인하고 수정 뒤 통과를 확인했다는 표현입니다. 실행되지 않은 테스트는 실패를 재현한 근거로 삼지 않습니다.

**코드 실행 비율(coverage)**은 테스트가 소스의 어느 부분을 실행했는지 나타내는 값입니다. **검사 기준(gate·threshold)**은 통과 판정에 사용하는 조건입니다. 실행 비율이나 테스트 통과만으로 모든 입력·기기·공격 상황을 확인했다고 해석하지 않습니다.

실제로 수행한 검사와 아직 확인하지 않은 범위는 [검수 기록](validation.md)에 구분합니다. 패키지 사용은 [문서 목차](README.md), 모듈 구조는 [전체 아키텍처](architecture/README.md)에서 이어 읽을 수 있습니다.
