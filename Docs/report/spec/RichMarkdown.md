# RichMarkdown 동작 명세

기준일: 2026-10-06 · 현재 구현의 계약입니다.

대상은 공개 패키지 구성품(product)인 `RichMarkdown`이며, UI의 최소 지원 버전은 [Package.swift](../../../Package.swift)의 iOS 16입니다. [아키텍처](../architecture/RichMarkdown.md)는 공통 처리 흐름과 UI 차이를, [ADR](../adr/README.md#richmarkdown-adr)은 현재 선택의 의미를, [개선 기록](../improvements/RichMarkdown.md)은 반영한 변경을 설명합니다.

각 ID는 요구 사항을 찾아 연결하기 위한 번호입니다. 아래 테스트는 현재 소스에 작성된 확인 코드이며, 실제 실행 결과는 [검수 기록](../validation.md)에 있습니다. 테스트 코드가 있다는 사실만으로 동작 통과·성능 측정·전체 기능 승인을 뜻하지는 않습니다.

이 문서에서 구문 분석(parse)은 Markdown을 문단·표·수식 같은 구조로 읽는 처리입니다. 캐시(cache)는 이미 만든 결과를 재사용하는 저장소이며, 같은 결과를 찾는 비교값을 키(key)라고 합니다. 화면 표시 결과가 없을 때 원문으로 대신 보여 주는 처리를 대체 표시(fallback)라고 합니다.

수식의 비트맵 이미지(raster)는 픽셀로 만든 그림이고, 윤곽선 그림(vector)은 선·글자 모양을 직접 그리는 표현입니다. 본문 안에 놓는 수식은 inline, 독립 블록으로 놓는 수식은 display 또는 block이라고 합니다.

## 확인 범위

문서가 갱신될 때마다 누적 원문 전체를 분석합니다. 구문 분석 캐시, 최신 대기 작업 하나로 합치는 처리, UIKit 뷰 재사용이 있어도 바뀐 부분만 분석하는 증분 구문 분석기는 아닙니다. SwiftUI와 UIKit은 수식 표시 방식·선택·OS별 코드 배경도 다릅니다.

[StreamingBaselineTests](../../../Tests/RichMarkdownTests/StreamingBaselineTests.swift)는 처리 시간의 비교 기준(timing baseline), UI 상태를 담당하는 MainActor가 멈추지 않고 응답하는지(heartbeat), 스트리밍 계약을 확인하는 코드를 포함합니다. 이를 이번 실행에서 측정한 수치로 제시하지 않습니다. 유니코드 문자 값(scalar)·소스 조건 검사만으로 실제 스크롤·선택·VoiceOver·화면 표시 비용이 수용 가능한지 판단하지 않습니다.
